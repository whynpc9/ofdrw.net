# R19 复杂公开表格：设计检查点

基线：`123c8cf26a3d6b19ccdc0d4c2068a9e446b550d9`（包含 R04、R21、PR #48）。本计划在实现前固定公开语义和失败边界；功能、视觉、包消费验收仍待本分支代码及本次产物证明。

## 范围与兼容

- 仅扩展 `Ofdrw.Net.Layout.Table`。旧表（无纵向合并、无图片、未开启拆行或重复表头）继续走当前整行分页路径，保持 Native DOCX 的 `vMerge` 诊断、`tblHeader` 不重复及它独立的字体、字段和边框策略。双层 DOCX/PDF 不因本项宣称新能力。
- `Cell.RowSpan > 1` 把一个格占据的连续行合并，允许同时 `ColumnSpan > 1`。有纵向合并关系的连续行构成不可拆的组：剩余高度不足时整组换页，组高超过新页正文区时明确拒绝；不把一个纵向合并格切成两页。
- 表格新开关 `SplitRowsAcrossPages` 默认 `false`；只允许没有纵向合并的正文行按已测得的文字行边界拆分。不可分图片不能截断；无法让任何内容在新页片段前进时失败。拆分行的格内垂直对齐限定为 Top，避免全行 Center/Bottom 的不可证明跨页语义。
- `RepeatHeaderRowCount` 默认 `0`，仅表首连续完整行可重复。表头纵向合并只能留在表头内部，不能跨表头/正文边界；表头与至少一个正文片段必须同时容纳，不能产生只有表头的页。重复表头是物理重绘，OFD/PDF 提取文本按可见副本重复；扣除指定副本后的逻辑源文字仍须完整且各出现一次。
- `Cell.Image` 使用 R04 的 `ImageBlock` 已拷贝字节及准入规则，首版为图片单元格（不与该格段落混排）。宽高固定，不自动缩放；水平按图片 `Alignment` 放在内边距内，整格按 `Cell.VerticalAlignment` 定位。图片过宽/过高或无安全放置位置明确失败。
- R21 的 `TextPrelayoutEngine` 当前只接受有界的单一静态 face、统一 run 与限定 script；公开 Flow Span 仍使用 `FlowParagraphLayout`。本项保存且复用每行最终 `FlowLine` 测量结果，绝不为拆分结果重新估算字宽或称为真实复杂文字 shaping。

## 有界布局与绘制

1. 对逻辑表格一次预扫描：确认总列宽、跨度正数、网格全覆盖且不重叠，并限制 `行数 × 列数`、累计单元格、图片编码总字节。逐格测量文字和图片并保存结果；多行格的所需高度约束确定性地补到其末行，计算不可拆的纵向合并组。
2. 先确定当前页可容纳的组/行片段；新页重复表头占用实际高度。拆分候选只取所有格内已测文字行/图片的安全边界，候选不得穿过任何文字行或图片。每轮至少消费一项源内容或结束该行，片段数与页数有固定预算并检查取消。
3. 每个片段先绘制所属单元格底色，再放原文字行/图片，最后画边框。纵向合并的内部横线不穿过合并格；水平合并的内部竖线不出现；每个跨页片段有独立封闭的页顶/页底外框，所有路径保持在正文边界。`OnElement` 对每个最终物理行片段调用一次，`OnPage` 仍每页一次；失败不返回部分包。
4. 不修改共享 `FlowTableLayout.MeasureRow` 或 Native 渲染语义，新增公开表格专用布局路径。既有表格路径只有明确新能力被使用时才切换。图片由当前 `OfdGraphics.DrawImage` 的同一编码准入和资源机制创建，重复表头的每份物理图片遵守图片及片段预算。

## 验收样例与门槛

- 小型确定性公开表样例覆盖横纵混合合并、页尾行组整体移动、三页重复表头、长行真实拆分、图片格、中英比例字体及局部粗斜/颜色、底色与边框、表后正文。用既有 `generated-layout.docx` 跑显式 Native 与默认兼容基准。验证 OFD 保存重读和 PDF 提取文本按页对应；明确扣除表头副本后的原文断言。
- 反例：跨度越界/重叠/缺格、表头跨正文、仅表头能放下、超高纵向合并组、超页图片、拆行无前进、Center/Bottom 拆行、非法尺寸、各项预算、取消。旧 Table 和 DOCX Native 回归保持。
- 运行受影响测试、全套共享排版回归及精确单候选 manifest 的本地隔离包消费。所有本次 OFD 导出 PDF 和逐页 PNG；在 macOS Preview 逐页查看本次实际产物，分别记录功能、自动渲染、PNG 和 Preview 结果、页码/样例/模式、源码 SHA、大小与 SHA-256。失败不得称为完成。
