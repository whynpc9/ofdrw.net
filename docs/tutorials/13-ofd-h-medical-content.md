## 规范位置

征求意见稿第 7 章医疗应用要求（基本结构、资源、数据内容、附件、机读、版本）。

## 结构上多出来的钉死项

在 GB/T 33190 的树上，轮廓额外要求：

- `OFD.xml` 根节点 `DocType="OFD-H"`
- 字型、图像、音视频、模型等 **都在包内或按本课规则外链**，并登记在 `PublicRes.xml` / `DocumentRes.xml` / `Page_N/PageRes.xml` 与对应 `Res` 目录
- 元数据写在 `DocInfo` 或其引出的 `DocInfo_N.xml`
- 病历结构自定义标引放 `Tags/`
- 附件放 `Attachs/`
- 注释放 `Annots/`

这些目录能在 [第 9 课](09-templates-attachments-tags.md) 和 [第 8 课](08-images-and-resources.md) 里对上号。本仓库有附件和 `CustomTags` 写入；页级 `PageRes.xml`、元数据引出文件、注释目录尚未做成一等 API。

## 资源：能显示就能带走

轮廓的核心是 **离开医院内网也能显示打印**：

- 多页共用的字型、绘制参数及共享资源，在文档资源列表登记；仅一页使用的，一般登记在该页 `PageRes.xml`
- 显示打印所需 **全部字型数据应包含在文件中**，除非同时满足：字符落在格式标准规定的豁免字符集，**并且** 字型落在豁免字型列表（具体名单以 GB/T 33190 及其引用为准，本稿不另开一张表）
- 图像资源同样应包含在文件中
- 版式内图像限于 **BMP、JPEG、TIFF、PNG**，其它格式先转再嵌入
- DICOM 影像 **不宜塞进版面图元**，宜外部附件或文件链接，并独立于 OFD 存储
- 音频/视频采用或转为 MP3、MP4 等；影像、音视频、三维模型的清晰度要满足病历准确性，数据内置或关联可信时间源（稿中举例北斗）

对照本仓库：

| 轮廓 | Ofdrw.Net 现状 |
| --- | --- |
| 字体嵌入为原则 | 可嵌入 `OfdFontResource.Data`，无子集化，也无豁免列表检查 |
| 页级 PageRes | 图像默认进 `DocumentRes.xml` |
| 图像四格式 | 按调用方字节写入，不强制转码 |
| DICOM 外置 | 无专用类型，只能当普通附件 |
| 音视频/3D | 未建模，可能进 `PreservedEntries` 或 Raw |

源项目 `ofdrw-font` 更接近“把字形带上”；`ofdrw-layout` 的 `Img` 仍是通用图，不会自动处理 DICOM。

## 双层扫描件

纸质或设备扫描件：转换时宜把扫描图放在 **背景层**，OCR 文字放在 **正文层**。这就是第 5 课的 `Background` + `Body`，加上第 6 课可抽取 `TextCode`。

本仓库 PDF→OFD 的双层（页图 + 透明文字）和 DOCX `DualLayer` 与这条同构。Native DOCX 路径则直接写可见文字，适合系统内生成的文书，不适合扫描件。

不要把“只有一张整页图”的包叫做符合轮廓的数字化病历：检索和机读会失败。

## 页面上看见的，和机读的，要一致

呈现应与传统纸质同类文件相同或相近，同时：

- 元数据标明服务对象（患者）、责任者、生成时间、关键词
- 包含文件类型、保密等级、文档标识
- 不同类型的结构化数据，宜用 **自定义标引或附件** 存放，并与页面内容一致
- 宜包含责任者或医疗机构的签章/签名（生效信息）
- 需要 DICOM/音视频/三维时，应有文档内或外部跳转动作
- 不应禁止元数据著录、注释、文档组合和签名；必要时把多个文件组装成符合归档要求的 OFD

机读信息若以文件存放，应可准确识别；描述用 UTF-8。多项组成时应能区分文件头（版本、创建/修改时间）、元数据、标识（类型、密级、唯一识别码）。明细组织要便于程序检索，并符合卫生行业现行数据标准——本稿不代替那些行业数据集。

版本：若用版本记录内容或注释变动，应保留历史版本全部内容，或把历史修改作为 **内部附件** 保存。不要只改当前页还宣称可追溯。

## 附件

支持与医疗活动相关、但不是版面文书本身的文件；内部、外部附件都要能描述。体积大或需专用阅读器的资料（DICOM、长视频） **宜外部附件**。

本仓库 `OfdAttachment.IsExternal` + `ExternalPath` 对应外置；内部附件把字节写进 `Doc_0/Attachs/`。交换时按患者封装的那一份 OFD，附件列表必须还能解析，否则院际只拿到“空壳版面”。

## 动手

在一份病历 OFD（使用你有权使用的非隐私样本）上查：

1. `PublicRes.xml` 是否声明字体且 ZIP 内有 `FontFile`
2. 扫描页是否同时存在整页 `ImageObject` 与可复制 `TextCode`
3. `Tags/` 或 `Attachs/` 里的结构化内容能否与某页标题对上
4. 是否把 `.dcm` 误当成 `ImageObject`

系统内生成文书时，优先 Native 文字而不是整页栅格，这样更接近“结构可机读”。

## 常见坑

- **只改 DocType 为 OFD-H，字体仍靠客户端宋体**。换一台没有该字体的工作站，病历缺字，轮廓视为不合格。
- **把 JPEG 以外的 WebP/GIF 直接嵌入**。先转成四格式之一。
- **PACS 图塞进 Res 当 PNG，却丢掉 DICOM 头**。轮廓要求影像独立存储并用链接/外附件描述。
- **自定义标引与版面文字不一致**。机读诊断和印在纸上的诊断必须是同一事实，否则交换和归档都会错。
- **用注释当版本库**。注释可以加在签名之后（下一课），但不能替代完整历史或内部附件。
