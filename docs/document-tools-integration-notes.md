# Issue 03 integration with parallel Issue 02

Issue 03 was built independently from main. PR #12 overlaps PR #11 in `src/Ofdrw.Net.Converter.Pdf/Converters/OfdToPdfConverter.cs`. Issue 03 does not modify `OfdSignatureAppearanceReader` or the Issue 02 worktree.

The PDF changes are confined to ordinary page elements: object-local Clips for text/path, complete glyph CTM, generated faux-italic factor compensation, and explicit failure for a whole unsupported annotation drawing. The signature-appearance preparation/decoding and decoded image budget stay with Issue 02's strict image-export policy. When integrating, retain both the strict opt-in/export budget behavior from 02 and 03's ordinary element drawing behavior; preserve existing default signature payload compatibility and cancellation/error propagation.

Relevant contracts:

- `OfdElement.ClippingXml` is OFD object-boundary coordinates before the object's CTM. `OfdImageElement.ClipsXml` keeps its getter/setter as a forwarding alias. Text/path null preserves source clip XML; empty clears it. Images retain their existing authoritative clip behavior.
- Appearance flattening appends independent Clip intersections for the exact transformed outer box and image's original implicit boundary. It never uses a larger AABB as the actual clip.
- `https://ofdrw.net/style-hints` / `FauxItalicMatrixV1` stores the actual complete matrix generated by Writer. PDF/SVG transform glyph anchors by that factor and remove it from the glyph graphics matrix; semantic italic remains. Unmarked user CTMs remain fully applied.
- Annotation lists/files are indexed/cached per read. Supported visible annotation text joins extraction. ID-only PageBlock is bounded; unknown metadata preserves roundtrips, and unknown drawing cannot produce a partial successful export.
- `OfdPackagePruner`, `OfdResourceCatalog`, and Writer only mutate declared or verified implicit OFD annotation/resource/template entries. Unrelated/vendor same-name XML remains byte-preserved and participates in conservative liveness checks.
- CLI additions live in `DocumentTools.cs` through the small `Cli` partial class. The 02 command additions can be combined without restructuring shared dispatch or options.

Current verification and Preview state are in `docs/evidence/document-tools/acceptance.json`. Preview stays mandatory and unresolved while the Mac is locked. These notes are an integration checklist, not evidence that the two independent branches have already been merged or validated together.
