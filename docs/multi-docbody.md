# Multi-DocBody selection profile

`OfdReader.ListDocumentsAsync` lists the `DocBody` declarations in OFD.xml order. Each descriptor contains a zero-based index, normalized `DocRoot` path, optional title and signature-list paths. Listing is an inventory, not a validation or signature trust result. Missing, duplicate and case-aliased `DocRoot` paths are rejected. `OfdPackageLoadOptions.DocumentIndex` selects a zero-based document for Reader and the PDF, SVG, HTML and image exporters. Existing calls default to index 0; page indexes remain relative to the selected document. The CLI exposes a **one-based** `--document N` for these OFD reading/export commands, `extract-text`, `reorder` and `watermark`.

## Edit boundary

`OfdDocumentEditor` edits the selected `OfdDocumentPackage` in memory. `OfdPackageWriter` accepts an imported multi-document package only when each DocBody root is in a distinct top-level directory, all package entries belong to one of those directories or OFD.xml, the XML-looking entries have no references resolving into another document directory, and the package has no signature declarations or `Signs` payloads. It checks these conditions and compares every unselected document entry and DocBody subtree before output. An unsupported case throws `NotSupportedException` before writing the output stream. The target should still be staged atomically for final copy/I/O failures.

This intentionally narrow profile permits selected page reorder and watermark. It does not authorize multi-document `Split` or `Mix`, cross-document navigation/annotation/resource migration, shared-root resources, or signed-package editing. Those paths keep their separate restrictions. The explicit whole-package `clean-signatures` operation and verifier still traverse all DocBodies. The password-v2 profile still requires a single DocBody. No signature is claimed valid after an OFD.xml rewrite; to edit a signed package, the caller must explicitly choose the existing whole-package signature-cleaning workflow first.

PDF/SVG/HTML/image export reads only the selected Reader projection. PDF and image seal appearances are taken only from the selected DocBody's signature lists, even when another document uses the same page IDs. A cross-document resource path that the Reader can resolve may be rendered, but editing and repacking that package is rejected under the isolated edit profile. Format-specific rendering limits in [the capability contract](capability-contract-v12.md) remain in force; selection does not turn preserved unknown XML into supported drawing content.
