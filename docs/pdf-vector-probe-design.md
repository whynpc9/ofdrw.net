The task prohibits GUI, so macOS Preview, full readable CJK/local-style fixture acceptance, dual-layer comparison, default/native DOCX regression and release acceptance remain **not performed**. Synthetic success is not evidence of arbitrary PDF fidelity.

## Public bridge and why collection extraction is insufficient

Use a custom `BasePageFactory<T>` with a custom `BaseStreamProcessor<T>` and a strict parser. The internal built-in `ContentStreamProcessor` cannot be subclassed externally. Public `RenderGlyph` supplies `IFont`, character code, original mapped Unicode, font size, rendering matrix, text matrix and CTM; public path callbacks retain operator interleaving. Reading separate `Page.Paths` and `Page.Letters` and concatenating them loses the unified paint order.

The factory injects `PageContentParser(new StrictOperations(), new StackDepthGuard(64), false)`; `StrictOperations` wraps `ReflectionGraphicsStateOperationFactory` and throws if it returns null. An operation whitelist after `Page.Operations` alone is **not sufficient**, because PdfPig's default parser may have already discarded unknown operators. Every unsupported operation, including one before the first supported draw, must fail/fallback the whole page.

PdfPig's `ShowTextInternal` substitutes a character cast if `TryGetUnicode` fails. A bridge must repeat and require successful Unicode mapping; it must not treat a nonempty callback string as proof of source text. The probe rejects multi-scalar mappings and checks native glyph identity for the narrow Identity-H profile. The probe emits one original scalar per text event at that glyph's supplied baseline, exposing a Reader limitation: standalone whitespace TextCodes disappear on read-back. **Production must group compatible glyph callbacks from each Tj/TJ into one original-Unicode Text event with explicit advances**, derived in the first baseline affine coordinate system, and validate actual Reader round-trip. Mixed fonts/matrices/baselines or unsupported combining/shaping must fail/fallback; run grouping is required for this whitespace contract, not merely an optimization.

Coordinate conversion: PDF user space is points and Y-up. Map paths with `[a,-b,c,-d,e,H-f]` into Skia Y-down coordinates, then adapter `MillimetersPerUnit=25.4/72`. For text, combine PdfPig `textMatrix.Multiply(ctm)` in its row-vector convention; reverse the glyph-local Y axis as well, giving `[a,-b,-c,d,e,H-f]`. SKFont supplies font size; do not multiply it a second time through the rendering matrix. The probe allows default horizontal scaling/rise only. Supporting arbitrary text rendering matrices requires explicit composition tests. Crop offsets, page rotation and UserUnit need separate evidence or rejection.

## Narrow production profile recommended

A separate optional **`Ofdrw.Net.Converter.Pdf.Vector`** package may depend on existing PDF converter plus Graphics.SkiaSharp/Layout. No Skia reference enters Core, Layout or the default `Ofdrw.Net.Converter` metapackage. Keep the current default PDF→OFD dual-layer API and CLI behavior unchanged.

Proposed API: `PdfVectorToOfdConverter` with `PdfVectorOptions`, `UnsupportedPagePolicy.Fail | RasterizePage`, and structured per-page result diagnostics. Expose page number, operation ordinal/name or byte offset where available, font-resource key, diagnostic code and selected disposition. Default explicit vector policy should be `Fail`; callers may explicitly select `RasterizePage`. The existing generic conversion interface can be implemented, with a separate report-returning overload. Do not hide fallback only in logging.

The first profile can restrict pages to zero-origin/unrotated MediaBox=CropBox, UserUnit=1, no annotations/groups/optional-content effects, bounded simple opaque DeviceRGB/Gray paths and horizontal fill text. Support M/L/cubic/close/rectangle plus ordinary fill/stroke only when parameter semantics match 04/19. Reject clip, ExtGState, image/Form XObjects, shadings/patterns, unsupported line style, transparency/blending, marked ActualText, text stroke/clip, nonidentity CID maps and unknown operations. Reject CTM changes while a path is under construction unless each segment's construction-time CTM is correctly retained; the probe's single-CTM paths do not prove that case. Page resources that override device color spaces must also be rejected or handled explicitly.

For a supported page, produce a complete bounded staged event/font batch and append only after validation. For an unsupported page, discard **all** staged native content and either fail with no final output, or invoke the existing dual-layer page renderer once and use that page as the entire result. Do not overlay native text/paths with an opaque full-page image or label a raster fallback as a vector page. A scanned/no-vector page gets an explicit raster/fail disposition, never an accidental blank-success page. True blank pages need their own documented disposition.

An API-only first delivery is feasible. Keep default CLI free of the optional dependency; if CLI vectors are required for ticket closure, ship an explicit optional tool (for example `ofd-pdf-vector --unsupported fail|rasterize-page --diagnostics report.json`) or an explicit extension mechanism. Do not advertise `--vector` in the existing CLI unless that command actually loads the optional implementation. API/tool names here are recommendations, not shipped contracts.

## Exact-font contract and missing 05 work

Require full embedded fixed TrueType bytes, Type0 Identity-H, CIDFontType2 and identity CIDToGID mapping, successful ToUnicode for each source code, and `SKTypeface.GetGlyph(originalUnicode)==sourceCID`. Glyph zero, missing mapping, ligatures/multiple scalars, vertical writing, unsupported subsets/encodings and ambiguous mappings fail/fallback. In this limited profile equality proves source and destination select the same glyph from the **same bytes**; a matching family name does not.

Resolve FontFile2 through the PDF resource/descendant FontDescriptor and scanner, decode without normalization, register those bytes once under an ordinal unique target `fontResourceId`, and create SKTypeface from the identical payload. Keep resource flags from actual face OS/2.fsSelection Bold/Italic bits and agreeing head.macStyle, as required by 19; PDF descriptor/style names and Skia weight thresholds are not a substitute. The existing adapter checks resource ID uniqueness, exact SHA256 payload and face flags. The input Text request must remain non-faux 400/false while true resource face flags are retained. No replacement resolver, cache, font parser, normalization or subset service is introduced here.

Missing 05 capabilities remain explicit: arbitrary CID/GID remapping, Unicode cmap reconstruction for PDF subsets, full TTC face selection, variable/CFF/Type1/Type3 support, general shaping/fallback, font licensing policy, shared subset/union/ID remap service and associated export/reading-font regressions. Full-font embedding costs size and does not establish 05 completion. The 5,256-byte synthetic font is not representative of a full CJK font's size.

## Limits before product implementation

The probe hardcodes a single local F1 resource and known fixture geometry. It is not a reusable untrusted-PDF converter, does not implement page fallback and does not establish inherited resource/form traversal, decode limits, cancellation responsiveness or valid rendering of every allowlisted path/text combination. The event trace is evidence for the actual generated fixtures only.

`BasePageFactory.Create` resolves/loads fonts and decodes page content before `ProcessPage`. Therefore downstream event-count limits alone do not bound earlier stream allocations. Production needs preflight byte/stream/font/page budgets, bounded decode or a restricted unfiltered profile, plus cancellation; compressed streams cannot be declared bounded merely because their compressed length is small. Factory resource unloading occurs after successful processing without a surrounding failure `finally`; after an exception, discard/reopen the PdfDocument for the selected page/fallback rather than reusing uncertain resource-stack state. Record the reopen cost. The independent custom processor must release native paths on all rejection paths. A preferable production alternative proposed by the coordinator is a context-only public `IPageFactory<T>` bootstrap exposing the injected scanner/store/parser and page dictionary/tree members, followed by bounded stream preflight and controlled resource loading/unloading before invoking the processor. This avoids relying on BasePageFactory decode timing; that alternative is a product design recommendation, **not an executed part of this probe**.
