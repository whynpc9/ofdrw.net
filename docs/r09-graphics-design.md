# R09 graphics image and pen design checkpoint

Source baseline: `58c488f52bfeffab965292de8dd7a65f439597e1` (merged R01). This document defines the new public drawing contract before implementation. The current [capability contract](capability-contract-v12.md) rejects imported gradients and patterns; that rejection remains authoritative until each export has its own tested support.

## Image placement

`OfdGraphics.DrawImage` accepts the shared static-preview PNG profile or gray/RGB baseline JPEG without EXIF/ICC/Adobe metadata, a positive destination rectangle in user space (millimeters), an optional source rectangle in encoded pixel axes, and opacity 0–255. Embedded DPI does not change the pixel axes. The source rectangle must be inside the encoded dimensions, have positive size, and remain positive at writer precision. Invalid or unsupported image data and budget overruns fail before a page object is appended. The call snapshots bytes; subsequent caller mutation has no effect.

The image's unit square maps through source-to-destination scaling and the current user-to-page transform. The OFD image Boundary is the finite bounding box of the transformed destination corners; its CTM is rebased to that Boundary. A destination-rectangle clip, frozen at call time, intersects the existing clip stack so rotation, reflection and source cropping cannot reveal pixels outside the requested placement. Cropped placements retain the exact requested source mapping, including fractional pixel boundaries, and carry a canonical PDF crop hint. PDF export creates a bounded, edge-padded nearest-sampled image for that placement so macOS Preview cannot filter neighboring pixels across the clip; other exporters continue to use the original image and CTM. The OFD keeps the original encoded bytes and shared media resource. A fresh Preview check is still required. `Save/Restore` continues to save transform and clip state only. Image bytes enter the existing writer resource planner, which deduplicates equal format+content while retaining distinct placements. PNG/JPEG validation happens before append and is bounded by the context's encoded-byte and pixel limits.

## Pen

`OfdPen` retains its existing solid butt/miter defaults. New immutable cap, join, miter, dash and dash-offset values are per-pen; graphics state does not inherit them. Numeric validation follows writer precision and PDF's representable subset: finite positive dash lengths and line width, nonnegative offset, bounded miter. The path Boundary expands for the configured stroke envelope under the full affine matrix. New attributes use the existing PathObject source XML slots, so Reader, writer, SVG and PDF parse the same values. Unsupported combinations fail before append or at the affected export, never render as a different solid line.

## Gradient and pattern checkpoint

R01 resolves flat GRAY/RGB/basic CMYK and palette colors, and explicitly rejects unknown native gradient/pattern semantics at PDF/SVG/HTML. A future native gradient/pattern brush therefore needs a typed resource and object paint model, writer ownership, readback projection, exact coordinate space, clip interaction, opacity, and separate PDF/SVG/HTML rendering. The provable R09 subset is explicitly **rasterized rectangle fill**: two-stop horizontal/vertical RGBA linear gradient sampled into a bounded PNG, and PNG/baseline-JPEG image tiles repeated at bounded user-space sizes. Both use ordinary ImageObjects, existing resource deduplication and export paths, with no silent pure-color substitution. This is not native OFD shading or arbitrary path/pattern support. Imported native gradient/pattern nodes continue to fail per R01. The public method names disclose the rectangle-only raster semantics; sampling and tile counts are bounded.

## Acceptance

Use fixed, redistributable quadrant pixels and an independent visible line sample. Assert source crop, transformed CTM and clip, opacity, `Save/Restore`, failure atomicity, and one media payload for repeated placements. Check PDF, independent SVG and HTML separately, including unsupported cases. Inspect every newly generated PDF page in macOS Preview and every PNG page; record actual paths, hashes, pages, source SHA and closed windows. Run affected tests, full regression and local package consumer E2E before PR closure. This plan does not itself constitute functional or visual acceptance.
