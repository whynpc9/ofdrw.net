# R08 direct TrueType GID outline profile

This increment defines an internal, operation-owned reader for an **original glyph ID** in a static, monochrome TrueType `glyf`/`loca` face selected by explicit collection face index (zero for a standalone font). It returns unhinted design-unit contour points, source and selected-face SHA-256 identities, face index, units per em, advance width, and a shared quadratic path-command projection. It does not choose a GID from Unicode, reshape text, or infer logical text from geometry. The caller must keep `TextCode` and any `CGTransform` source XML independently.

The reader bounds the source at 64 MiB, selected face at 16 MiB, one glyph at 32,768 decoded points, 4,096 component visits, and composite depth 16. It rejects invalid GIDs, cycles, malformed tables and glyph ranges, point-attached composite placement, ambiguous scaled offsets, and CFF/variable/color tables. A zero-contour glyph returns an empty outline rather than a substitute glyph. Cancellation is checked during glyph and component visits.

The parser follows the [OpenType `glyf` simple and composite descriptions](https://learn.microsoft.com/en-us/typography/opentype/spec/glyf), [`loca` offsets](https://learn.microsoft.com/en-us/typography/opentype/spec/loca), and [`hmtx` advances](https://learn.microsoft.com/en-us/typography/opentype/spec/hmtx). This first profile accepts simple glyphs and XY-translated components. For a composite with `USE_MY_METRICS`, it reports the designated component's advance; multiple designated components are rejected. It validates the trailing instruction range when any component advertises instructions, but does not execute them. Point-attached or transformed composite placement and device-grid hinting remain unsupported for direct GID drawing.

## Fixed independent oracle

The existing OFL `e2e/Ofdrw.Net.FontSubset.E2E/testdata/fonts/NotoSans-Regular.ttf` is pinned by its adjacent upstream manifest. Its SHA-256 is `b85c38ecea8a7cfb39c24e395a4007474fa5a4fc864f6ee33309eb4948d232d5`. Developer-only fontTools `getCoordinates` produced these reference hashes from every flattened point (`int32` big-endian X/Y plus one on-curve byte), then each contour end index (`uint16` big-endian):

| Glyph | Original GID | Points | Contours | Advance | Oracle SHA-256 |
| --- | ---: | ---: | ---: | ---: | --- |
| `A` | 36 | 18 | 2 | 639 | `87b232a19336c343b39518ca59c94dc2743de3a8bd8d00c086a937b1a4595426` |
| `fl` ligature | 1653 | 28 | 2 | 602 | `165e09631437760eb62a355f43e5863cca58eb110d05186dabefbd5cbbefd317` |
| `é` | 171 | 43 | 3 | 564 | `55ce309c6236a9598dff429b59668ec927fc9f5c9b1f22af06426e6e98dbfe60` |

The `fl` GID is a substitution result, with no direct scalar in this font's Unicode cmap. Its successful extraction demonstrates that the reader is GID-driven. The `é` outline includes its accent component and `USE_MY_METRICS` component. The tests also check the metric override, instruction-range validation, fail-closed point-attached placement, and cancellation.

The existing MIT `style-collection.ttc`, generated by `scripts/generate-font-test-fixtures.py`, checks explicit face-index zero and separate source/selected-face identities. Its glyph 2 has four points, one contour, advance 500, and independent fontTools point hash `ccb1267561e0ca4aa464c3c056ec7f2d6c2a5e62917c18bd50db393d8bdc1660`. A nonexistent collection index is rejected.

## Four-outlet boundary at this increment

| Outlet | Status |
| --- | --- |
| OFD save | Existing source XML, font bytes, and logical text preservation remain in place. This increment does not add typed `CGTransform` editing. |
| SVG | Direct GID export is not wired; `CGTransform` still fails closed. |
| PDF | Direct GID export is not wired; `CGTransform` still fails closed. |
| Outline | The shared static TrueType reader supplies original-GID points and quadratic path commands for supported glyph forms. No reader or export acceptance is inferred from this API alone. |

R02 still needs a complete foreign `CGTransform` OFD with a licensed original font and independent reader result, plus validated Unicode-sequence and glyph-position semantics. A synthetic font oracle is a code regression input, not that independent document acceptance.
