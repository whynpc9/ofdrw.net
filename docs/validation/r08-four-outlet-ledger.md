# R08 font backend: four-outlet capability ledger

This ledger describes the selected input profiles merged through [PR #51](https://github.com/whynpc9/ofdrw.net/pull/51) at `319b4b67`. The v1.2 research input (`artifacts/roadmap-v12-20261021/research-v1.2.txt`) calls for choosing non-BMP, symbol cmap, bare Type1/CFF, and glyph-outline routes **from actual inputs**. It asks for separate OFD save, SVG display, PDF embedding/text, and outline conclusions. A working font name, a saved OFD, or a rendered PNG establishes only its own cell.

`limited` below means the named input and outlet have a bounded, tested route. `unsupported` means the outlet rejects or lacks the route. `unverified` means bytes or a model can be retained without evidence of that outlet's semantics. The source identity, logical Unicode, `SourceXml`, resource IDs, embedding permission, parse budget, and zero-output preflight rules remain part of each profile. The [font subset contract](../font-subset-and-reuse.md) covers full/subset preservation separately.

## Evidence by outlet

- **OFD and PDF text:** [font subset evidence](../evidence/font-subset/README.md) and `FontIsolationTests.EmbeddedSupplementaryGlyphUsesOriginalOutlineAndExactPdfToUnicode` check original supplementary text, CID outline, surrogate-pair `ToUnicode`, and extraction. [NameOnlyFontBindingTests](../../tests/Ofdrw.Net.Converter.Pdf.Tests/NameOnlyFontBindingTests.cs) cover exact face snapshots and zero-output refusals. The [symbol profile](r08-symbol-cmap-profile.md) checks original bytes, direct PUA, PDF `FontFile2`, and extraction. No CFF PDF success is claimed.
- **Actual SVG pages:** the [symbol](r08-symbol-cmap-profile.md) and [CFF1 text](r08-cff-svg-text-profile.md) profiles record source and exact-package SVG hashes, pinned physical face, per-page raster images, visual observations, and refusals. Their trusted offline renderer checks the **actual generated SVG** with the exact face bound; source/package agreement is a separate check. This satisfies the selected SVG visual gate used for R08. Browser-specific embedded `@font-face` loading remains `unverified` and is not a required second visual gate. A historical local `file://` browser observation was denied by tool URL policy; do not retry it through another protocol or browser automation path.
- **Original-GID paths:** the [TrueType](r08-gid-outline-profile.md) and [CFF1](r08-cff-outline-profile.md) profiles pin original GIDs and compare commands or points against independent fontTools oracles. The CFF diagnostic PDF viewed in Preview is an outline-page check, not CFF text embedding.
- **Package, CI and review:** [PR #43](https://github.com/whynpc9/ofdrw.net/pull/43), [#46](https://github.com/whynpc9/ofdrw.net/pull/46), [#47](https://github.com/whynpc9/ofdrw.net/pull/47), [#49](https://github.com/whynpc9/ofdrw.net/pull/49), [#50](https://github.com/whynpc9/ofdrw.net/pull/50), and [#51](https://github.com/whynpc9/ofdrw.net/pull/51) have their own exact-head CI/review and local package-consumer receipts. The PR #51 candidate had 12 validated packages; the fresh PackageReference-only consumer checked OFD readback, byte-identical SVG, normal/over-budget HTML, and zero-output PDF/CFF and invalid-GID refusals. These are historical tested candidates, not a public NuGet release.

## Unsupported cells and future trigger

The repository has a licensed standalone `SourceCodePro-Regular.otf` (sfnt OpenType/CFF1), **not** a bare `.pfa`, `.pfb`, or `.cff` fixture. No bare-program positive route follows from it. Obtain an actual, redistributable bare-font OFD, source license, encoding/GID expectations, and independent reader or renderer oracle before choosing a bounded Type1/bare-CFF outlet. If there is no such input requirement, preserve `unsupported`/`unverified` and the explicit refusal. Positive CFF PDF, low-byte symbol fallback, name-only supplementary, variable/color/CFF2, arbitrary shaping, and `CGTransform` semantics beyond the [R02 bounded candidate](r02-cgtransform-profile.md) need separate profiles and evidence; format names alone do not authorize them.
