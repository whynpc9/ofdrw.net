# R08: bounded Windows symbol cmap export

This increment accepts an embedded static monochrome TrueType face selected by an OFD text object only when every TextCode scalar is a BMP private-use character with a direct Windows symbol cmap mapping. Each mapped GID must be in the face and unique across the private-use repertoire. The original font bytes and TextCode remain in the OFD. PDF and SVG use a Unicode cmap copy of the selected face; PDF restores the complete FontFile2 after PDFsharp's subset stage so nested composite components and the OS/2 no-subsetting flag remain intact.

Ordinary Unicode characters that happen to hit the symbol cmap's low-byte fallback, unmapped private-use characters, Type1/CFF, variable and color fonts, and ambiguous symbol mappings still fail closed. Name-only symbol bindings and CGTransform export remain outside this profile.

The focused regressions exercise direct private-use text, the existing low-byte refusal, exact OFD font preservation, a nested composite glyph, OS/2 no-subsetting, PDF FontFile2 bytes and extracted text, and the SVG embedded Unicode cmap. The source and local-package consumer generate one-page PDF and SVG artifacts from the same OFD under ignored `artifacts/`; their hashes and visual inspection are tracked in the R08 acceptance record. Automated text and cmap checks do not substitute for page inspection in macOS Preview or inspection of the actual SVG page with the exact embedded font bound in the renderer. The acceptance record also preserves the browser loading limitation and the result from the default renderer without that font binding.
