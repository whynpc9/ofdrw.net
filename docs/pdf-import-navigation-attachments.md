# PDF import: navigation and embedded attachments

Both PDF importers expose `PdfToOfdOptions.CopyBookmarks` and `CopyAttachments` through their compatibility options. Both switches default to `false`. The vector importer applies metadata to its final package after it has selected native or whole-page fallback output, so a fallback page does not import a second copy.

With bookmark copying enabled, a PDF outline's hierarchy and title are copied into OFD `Outlines`. A local page destination is mapped to the first retained occurrence of that source page. The supported destination forms are Fit, FitB, XYZ with both coordinates or neither, FitH, FitBH, FitV, FitBV and FitR. Coordinates use the displayed CropBox after page rotation. A target outside the selected pages, an external or named target, an unsupported action, or a malformed/omitted outline node fails the conversion before writing the output stream. `MaxBookmarkCount` and `MaxBookmarkDepth` bound the copy.

With attachment copying enabled, document embedded files and selected-page `FileAttachment` annotations become embedded OFD attachments. A page occurrence gets its own attachment and a local link annotation with a `GotoA` action pointing to that attachment ID. The link draws a generic PushPin inside the source annotation's displayed rectangle; custom PDF annotation appearances are not copied. Names are reduced to a basename; case-insensitive collisions receive a deterministic ` (2)`, ` (3)` suffix. Raw and plain Flate streams are supported. External files, other stream filters and filter parameters fail explicitly. `MaxAttachmentCount`, `MaxAttachmentBytes` and `MaxTotalAttachmentBytes` bound decoded payloads. The output stores decoded bytes, so payload identity can be checked by hash after an OFD reader round trip.

Unselected page annotations are not copied. Other PDF annotation types retain the existing vector mode policy: fail or whole-page fallback. Turning either switch off leaves that category out of the OFD model. A generated `GotoA` is checked against exactly one retained local attachment before package writing; ordinary page graphics do not gain a supported attachment reference from the annotation profile.

The profile establishes model and package readback for the covered inputs. Visual output, macOS Preview viewing and behavior in an independent OFD reader require separate acceptance evidence for each generated artifact.
