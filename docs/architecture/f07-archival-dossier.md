# F07 归档证据档案：有界实现与外部准入

Issue #109 的 F07 独立于 R22。当前实现的具名 profile 为 `ofdrw-archival-dossier/1`：真实消费者使用 Packaging NuGet，输入为稳定源/结果 OFD 和显式证据流，输出为可序列化的条款与证据索引。不增加 native 或 NuGet 依赖。它交付证据登记与追踪层，**不关闭 F07 全部标准覆盖工作**。

标准基线沿用已核对的 GB/T 42133-2022 主标准及其 SHA-256（见已有规则和覆盖账本）。账本 105 项保留同一条款身份、条件和缺口，17 项 AR/AC 结果自动关联；测试比较完整账本内容，避免遗漏条款或不同步。APF 不自动升级为标准规则。引用标准没有假定“最新版本”：目标 profile 需逐项填写版本及修改单；GB/T 20090 按附录音视频的适用部分评估。登记版本只是声明，获准使用的正文、勘误及适用性仍需外部评审。

源/结果先在累计预算内复制为独立内存快照，再计算 SHA-256 并运行原覆盖服务，确保摘要与被检查字节一致。证据按次读取计入同一累计预算；计算摘要但不保留正文。每项证据声明它针对的源/结果摘要，避免旧资料被当成本次证据。哈希和身份错配使证据完整性失败；材料为空、不完整或内容不真实不由哈希解决。调用方必须保存实际材料，报告不内嵌字体、证据或附件载荷。

条款报告区分软件子条件结果和完整条款结果。没有映射规则时子条件汇总为 NotApplicable（表示没有可运行子条件），完整条款仍 Unknown；无对象不会自动使条款通过。外部文件无论命名为 approval 或 policy 都保持 NotAuthenticated。材料角色的正/反/不确定例只是登记角色，不是库对测试有效性的背书。源报告、输出报告及证据完整性各自独立。所有已知输出违规继续 Fail，其余完整标准仍 Unknown。

停止条件：输入不支持由原覆盖服务报告 Unknown；参数有误、取消、证据数量或累计读取预算超限、普通 I/O 错误直接抛出，不返回部分档案。不得为完成覆盖而自动移除签名、删除附件、调用转换器、运行外部程序或信任外部 URL。已有 R17 副本和 R18 物理删除保持原有所有权契约。

## 尚待实施及外部材料

以下是 F07 剩余工作，不能用这次证据 API 的测试通过替代：

- 目标归档机构、接收范围/级别、引用标准适用版本与修改单、可使用的标准条款及政策核准。
- 字体表、真实字形、嵌入权限、媒体解码/扩展和资源闭包的条款级验证器；不能用文件摘要代替有效性。
- 针对适用附件类别的真实且可分发样例、对应转换 handler、保留/移除决策、顺序及信息损失说明。现有 DOCX 转换能力不证明附录全覆盖。
- 感知来源的 Versions 保留、动作迁移、扩展外观冻结等处理器，以及独立的正/反/不确定例。
- 独立阅读器、逐页视觉与 macOS Preview、目标阅读器 OFD-A 编辑锁及未处理项报告。
- 适用签章的格式标准、认证来源、合格 CA、吊销历史、可信时间与归档方长期状态服务批准。

补齐软件验证器需另有准确条件与真实语料。外部事实须由归档方及独立评审提供；当前环境没有这些材料，也不能伪造认证。无需因此恢复 R22 或扩展文字排版范围。

用户已确认目前只有官方标准，没有指定机构、接收政策或独立核准材料。profile 因此接受空机构并将其保存为 null；报告显式列出外部基础角色缺失和未评估条件。不得填入虚构机构或推断批准。登记文件与完成独立评估为不同状态；外部评估结论保持 Unknown。软件规则可按有依据的标准条件继续扩展，无需等待机构材料才能开发。
