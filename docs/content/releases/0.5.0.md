## 相比 0.4.0

- **默认 `DocType` 改为普通 `OFD`。** `OfdConstants.DefaultDocType` 和 `OfdDocumentOptions.DocType` 的默认值由 `OFD-H` 改为 `OFD`。通用文档生成、DOCX → OFD（Native 和 DualLayer）及 PDF → OFD 不再默认声明为电子病历 OFD-H。读取已有文件仍保留其显式声明；缺少 `DocType` 时按普通 OFD 读取。需要 OFD-H 时，须显式使用下文的 `MedicalDocumentProfile`。
- **保护 OFD-A 归档原件。** 页面重排、删除、裁剪、拆分、合并、叠加、文字替换、命名区域填充、水印、附件移除、签名清理和口令加密等改变内容的入口，会拒绝原始 `OFD.xml` 精确声明 `DocType="OFD-A"` 的输入，并抛出 `OfdArchivalOriginalException`。相应 CLI 命令不写输出并返回退出码 `5`；只读读取、提取、定位、验签、预检和格式导出不受影响。
- **显式派生普通 OFD。** 新增 `OfdOrdinaryDerivation.CreateAsync` 和 `ofdrw derive-ofd <input.ofd> <output.ofd> [--json]`。派生只把新文件根节点的 `DocType` 从 `OFD-A` 改为 `OFD`，其他包条目内容保持不变；输出必须是新文件，已签名或已加密输入会被拒绝。派生副本不继承原件的归档结论或签名效力。详见[页面与文档工具](/guides/document-tools/)。
- **Native DOCX 可选字体自包含。** 新增 `DocxConversionOptions.NativeFontSelfContainment` 与 CLI `--native-font-self-containment`。默认 `compatibility` 保留既有名称字体行为；`require-embedded` 要求 Native DOCX → OFD 中每个实际使用的字体资源都嵌入所声明字体族自身的字节，缺字节、跨族替代或字体嵌入限制会导致失败。该选项不适用于 DualLayer 或 DOCX → PDF，许可位允许嵌入也不等于获得授权。配置与诊断见[字体部署](/guides/fonts/)。
- **新文档的自定义标签改用中性键值通道。** 新写出内容使用 `ofdrw-kv`，不再新增历史 EMR 标记；已有 EMR 载荷继续可读，未修改的标签结构继续保留。该结构未对照 GB/T 33190 核验，不应仅凭标签形态推断标准符合性。详见[模型与读写边界](/reference/core-model/)。

## 可选归档评估

新增显式 opt-in 包 `Ofdrw.Net.Archival`。`ArchivalAssessmentService.AssessAsync` 对输入 OFD 的字节快照进行只读评估，分别报告原始 `DocType` 声明、输入 profile、逐条款观察、文档整体、软件要求、外部认可和执行状态；现有本地预检、已知 CustomTags 引用闭包和包内嵌入字体载荷检查纳入同一份报告。

- 首批输入 profile 面向单 DocBody、未签名、未加密且无附件、Versions 等扩展内容的简单文档。`OutOfScope` 表示超出该 profile，不等于违反标准；`Unknown` 表示证据不足、范围不完整或运行未完成。
- 条款级 `Pass` 只覆盖所映射的有界检查。没有可执行检查或仍需外部证据的条款保持 `Unknown`，第 7 章软件行为、机构接收、PKI 和独立核准不由单个文件证明。
- **文档整体 `StandardOutcome` 只有 `Fail` 或 `Unknown`，没有整部标准的 `Pass`。** 本包不生成、修复或改写 OFD-A，也不提供合规认证。字体检查不证明视觉正确性或嵌入授权。完整范围和结果解释见[归档评估](/guides/archival-assessment/)与[归档覆盖账本](/reference/archival-standard-coverage/)。

## 可选电子病历 OFD-H

新增显式 opt-in 包 `Ofdrw.Net.Medical`，面向 GB/T 48666-2026 的 OFD-H，提供两类彼此独立的能力：

- **写出 profile：** `MedicalDocumentProfile.Apply` 配置 `DocType="OFD-H"`、`/2016` 命名空间、`Doc_0` 目录、Deflate 压缩、线性化条目顺序和文档元数据。DOCX 转换入口仍生成普通 OFD；需要 OFD-H 时，应按指南转换、读取、应用 profile 后重新写出。profile 不嵌入字体、不签名、不生成双层页面，也不自动改变页面内容。
- **只读评估：** `MedicalAssessmentService.AssessAsync` 给出逐条款 `Pass` / `Fail` / `Unknown` / `NotApplicable`，并在同一快照上运行归档评估、按继承账本解释结果。**OFD-H 文档整体 `StandardOutcome` 同样只有 `Fail` 或 `Unknown`，永不给出整体 `Pass`。**

`MedicalEditPolicy` 另行提供编辑操作分类和授权检查，但通用编辑 API 不会自动调用它。评估不验证签名的密码学有效性，不证明阅读器、业务流程或引用标准符合要求；线性化只约束本库新写出的包，签名服务重写时不保持该顺序。资源表冲突、机读载荷、扫描件双层页面及 OFD-H → OFD-A 派生等边界见[电子病历 OFD-H 指南](/guides/medical-ofd-h/)。这些检测和 profile 均不等于合规认证。

## 升级兼容性与已知边界

- 默认输出声明由 OFD-H 改为 OFD 是可见的行为变化；依赖旧默认值的调用方应显式配置所需 profile，而不是把 `DocType` 标签当作符合性证明。
- OFD-A 保护只依据精确、区分大小写的原始声明，不验证文档是否实际满足归档标准。直接操作底层模型及 `OfdPackageWriter` 原样写出不经过全部编辑入口保护；追加签名的既有行为不变。调用方不能只依赖这些保护替代自身文档策略。
- 字体自包含是 opt-in，默认兼容行为不变。该策略只解决 Native DOCX → OFD 的字体载荷要求，不保证任意 Word 文档的版式保真，也不代替字体许可审查。
- 同系列包继续采用精确版本依赖范围，请一起升级项目中的 `Ofdrw.Net.*` 包。任意复杂 Word/PDF 保真、完整标准符合性、生产 PKI/签章法律效力及所有阅读器互操作仍不在普遍承诺内，参见[已知问题](/troubleshooting/known-issues/)和[能力契约](/reference/capability-contract-v12/)。

## 平台与包清单

普通 SDK 包以及新增的 Archival、Medical 包面向 `netstandard2.0` / `netstandard2.1`，CLI 仍要求 **.NET 10**。目标框架兼容不代表所有操作系统、RID、AOT 或单文件发布方式均已验证。

默认打包清单包含 14 个包：`Ofdrw.Net.Core`、`Ofdrw.Net.Packaging`、`Ofdrw.Net.Layout`、`Ofdrw.Net.Text.HarfBuzz`、`Ofdrw.Net.Reader`、`Ofdrw.Net.Converter.Abstractions`、`Ofdrw.Net.Converter.Docx`、`Ofdrw.Net.Converter.Pdf`、`Ofdrw.Net.Converter.Svg`、`Ofdrw.Net.Signatures`、`Ofdrw.Net.Converter`、`Ofdrw.Net.Cli`、`Ofdrw.Net.Archival` 和 `Ofdrw.Net.Medical`。

Archival 与 Medical 按需使用。`Ofdrw.Net.Converter` 等普通包的依赖图不含这两个包。引用 Medical 会沿 `Medical → Archival → Packaging → Core` 引入同批依赖。PDF Vector、Skia、Password 和 SES interop 仍是默认集合之外的独立源码扩展。ImageSharp 2.1.13 的既有已披露依赖告警仍需按[依赖评估](https://github.com/whynpc9/ofdrw.net/blob/main/docs/validation/d10-imagesharp-security-assessment.md)处理。

## 安装

```sh
dotnet add package Ofdrw.Net.Converter --version 0.5.0
dotnet tool install --global Ofdrw.Net.Cli --version 0.5.0

# 按需显式安装；Medical 会以精确的同批版本依赖带入 Archival
dotnet add package Ofdrw.Net.Archival --version 0.5.0
dotnet add package Ofdrw.Net.Medical --version 0.5.0
```

已安装 CLI 时使用 `dotnet tool update --global Ofdrw.Net.Cli --version 0.5.0`。请将所有 `Ofdrw.Net.*` 直接引用一起升级到 0.5.0。
