## 相比 0.2.0

- Flow、纯文本及 DOCX Native 新增**显式启用**的最终文字排版引擎。实际字体塑形和嵌入支持制表位、合成粗斜体、下划线、删除线、高亮、字距、静态 CFF 字体及增补汉字；默认排版入口不变。Flow 和纯文本的隐式制表位会在距前文不足半个 em 时跳到下一个制表位；DOCX Native 保留 Word 的制表语义。参见[启用指南](/guides/final-text-layout/)与[引擎范围](/reference/text-paragraph-layout/)。
- PDF→OFD 新增可选的 `VisualLineProfile`：仅在有界、可验证的水平 RTL 行上导入逻辑文字与来源字形位置。默认仍拒绝未验证的 RTL 语义。数字、组合标记、展示形式、不可见或裁剪文字、Form XObject 等情况继续明确拒绝；这不是通用 RTL 导入。参见[转换契约](/reference/conversion-contracts/)。
- 归档预检新增来源与证据档案的追踪模型及外部材料缺失门禁，便于记录源/结果身份、条款证据与未评估项。完整 GB/T 42133-2022 符合性、目标档案机构政策及外部核准仍未完成；结果不能称为认证。参见[归档覆盖账本](/reference/archival-standard-coverage/)。
- 修正最终文字排版中跨回退字体的高亮接缝和 Flow／纯文本制表位紧贴后续列的情况。已有 DOCX、PDF 和文字流程的其它回归也随候选参加完整 CI。

## 兼容性与依赖

SDK 继续面向 `netstandard2.0` / `netstandard2.1`，CLI 要求 .NET 10。默认发行集合包含 12 个 NuGet 包；Skia、PDF Vector、SES interop、口令加密仍是独立扩展。最终文字排版需要显式字体和 `Ofdrw.Net.Text.HarfBuzz`；不启用时维持原行为。ImageSharp 2.1.13 的五项已披露依赖告警尚未修复，见[依赖评估](https://github.com/whynpc9/ofdrw.net/blob/main/docs/validation/d10-imagesharp-security-assessment.md)。

## 已知限制

Preview Find、原始 Unicode Copy 与段落 PDF 选择几何仍无通过结论。最终文字排版不保证任意 DOCX 保真，复杂字体、其它阅读器及任意 RTL/Arabic/Indic 输入超出已验收范围。F07 的标准覆盖仍是部分追踪；PDF RTL profile 对未能证明视觉顺序的页面拒绝。详细边界见[能力契约](/reference/capability-contract-v12/)与[已知问题](/troubleshooting/known-issues/)。

## 安装

```sh
dotnet add package Ofdrw.Net.Converter --version 0.3.0
dotnet tool install --global Ofdrw.Net.Cli --version 0.3.0
```

已安装 CLI 时，使用 `dotnet tool update --global Ofdrw.Net.Cli --version 0.3.0`。

## 验收范围

本版的发布门禁包括源码绑定的功能测试、同批包消费，以及 DOCX 显式 Native 与默认模式各两页的 macOS Preview 逐页验收。新增排版及 PDF RTL 样例的既有验证范围和未完成项分别见[引擎比对](https://github.com/whynpc9/ofdrw.net/blob/main/docs/validation/text-engine-switch-comparison.md)和[RTL 导入验证](https://github.com/whynpc9/ofdrw.net/blob/main/docs/validation/f06-pdf-rtl-import-validation.md)；这些旧记录不代替 0.3.0 候选验收。
