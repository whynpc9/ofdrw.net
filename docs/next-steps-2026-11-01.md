## 2. 本轮发布范围与整体优先级

本轮交付的是一个具名版本及其**已验证的中英文使用范围**，不是完成全部 R00–R22。普通中文/英文文档的文字完整、可读、常用样式、表格、分页和安装使用优先于新脚本、新字体格式和通用排版架构。已有有限实现继续保留，延期不表示删除功能或放松既有拒绝/回归测试。

### 2.1 必须形成的可用场景

| 场景 | 本轮要求与现有基础 | 范围边界 |
| --- | --- | --- |
| SDK 生成中英文 OFD | 复用现有 FlowDocument/Paragraph/Span；中文、英文及混排，常规字号、段落换行/对齐、局部粗体/斜体/颜色、分页 | 验证已有能力并修复实际缺失；不以完成新的 HarfBuzz Flow 或全 Unicode 排版为前置 |
| DOCX → OFD | 显式 native 与默认模式均验证；正文、常见表格及底色/边框、内嵌图片、页眉页脚/页码和分页 | 复用 `e2e/Ofdrw.Net.Converter.Docx.E2E/testdata/generated-layout.docx`；不承诺浮动对象、任意复杂 Word 版式保真 |
| OFD 阅读、导出及文字可用性 | 主要检查 OFD → PDF/PNG 的正文完整性、常见样式、页序与可读性，核对 OFD 原文、PDF 复制及普通中英文搜索 | SVG/HTML、PDF→OFD、签章等保留已交付边界和回归，不扩大出口承诺；页末 Find 按 N02 单独判定 |

### 2.3 范围冻结与停止扩张

- **阻断发布的缺陷**：冻结的核心场景出现原文丢失/乱码/缺字、普通正文不可读、样式严重串染、裁切重叠/错误分页、无效输出、候选包无法消费，或现行必须通过的测试/发布门禁失败。不能用“只面向中英文”豁免这些失败。
- **不主动扩入的议题**：范围外脚本/高级字体、完整标准符合性、新架构统一、没有新证据的偶发根因、合成字重的进一步美化。明确记录限制，不把它们改写为已经支持。
- N00/N13 初次盘点最多 **8 小时（1 个工作日）的主动分析**，复用既有样例和证据，形成有限缺口表。之后每个改动必须对应表中一项；新增项只有构成上述阻断条件才加入。缺口表写明优先级、复现输入、预期、改动范围及投入上限，不能用“完善字体/完善排版”立项。
- 每项达到固定验收或投入上限就提交结果。到限未解决时停止该项探索，记录阻断/已知限制与下一步决策依据；不得自动换算法、追加矩阵或新建接力任务重置预算。真正的阻断仍未解决时诚实标记候选不可发布，不以超时证明通过。
- **历史量字 FAIL 保留，PR78 光学优化不再自动阻断路线图；但现行发布必验样例若仍有该视觉缺陷，N12 不能标 accepted。** 优先核对已有物理粗体及明确字体配置是否能满足核心样例的既定预期；不偷换原失败样例、不修改阈值，也不因此恢复轮廓算法研究。新样例通过与旧样例失败分开报告。
- 候选通过后进入发布准备，不再因为尚有未来议题而延长本轮。发布就绪、实际推包、公开源安装回读是不同结果，分别记录。

#### N06a 必须冻结的 Unicode 算法依据

本计划选择 **Unicode 17.0.0** 作为可复现的设计基线，不声称它是执行时最新版本或当前 SDK 已采用的版本。规范、属性数据和测试数据同版固定，记录下载来源、SHA-256、许可及适用勘误；升级另做差异验收。采用范围为 [UAX #9 revision 51](https://www.unicode.org/reports/tr9/tr9-51.html) 的 bidi、[UAX #14 revision 55](https://www.unicode.org/reports/tr14/tr14-55.html) 的默认断行机会、[UAX #29 revision 47](https://www.unicode.org/reports/tr29/tr29-47.html) 的 extended grapheme cluster；不默认承诺 UAX #29 的词/句分段。

**实现责任和选型出口：** N06a 执行者负责提交算法选型记录；N06b 在 Layout 的段落分析服务中接入或实现这些算法，HarfBuzz 仍只负责 run shaping。当前尚未选定算法库，不能将其写成已有依赖或绕过选型直接实现一般 bidi。选型记录必须给出实际库/版本/提交及其 Unicode 数据版本、托管/native 资产与许可、支持的规则和已知差异；若采用项目自实现，则给出模块、属性表生成流程、规则到代码的对应和测试计划。候选必须能固定到上述版本并通过一致性试验，不能从 `StringInfo`、OS 分词或 HarfBuzz cluster level 推定同版符合性。若库只能支持其他 Unicode 版本，先修订这一明确基线及全部匹配数据，不混用版本。

| 算法 | 采用范围与首版策略 | 一致性及产品验收 |
| --- | --- | --- |
| UAX #9 | 段落基方向、embedding level、弱/中性字符与括号、按已选行边界重置/重排；明确 Auto/LTR/RTL 参数。产品暂未支持的显式方向控制符在入口拒绝，不静默删除 | 对算法层运行同版 [BidiTest](https://www.unicode.org/Public/17.0.0/ucd/BidiTest.txt) 和 [BidiCharacterTest](https://www.unicode.org/Public/17.0.0/ucd/BidiCharacterTest.txt)，记录级别和重排结果；另验换行后的行级顺序、原文映射及已拒绝输入 |
| UAX #14 | 默认断行机会；首版无语言/地区 tailoring、无词典分词和自动连字符。依赖这些能力的文字范围明确拒绝；不把“溢出时任意切字”当默认策略 | 运行同版 [LineBreakTest](https://www.unicode.org/Public/17.0.0/ucd/auxiliary/LineBreakTest.txt)；另验行宽选择、强制换行、NBSP/标点、超长不可断片段的明确失败及断行重塑形 |
| UAX #29 | 默认 extended grapheme cluster，无定制边界；UTF-16 源索引与标量边界显式转换，不切代理对 | 运行同版 [GraphemeBreakTest](https://www.unicode.org/Public/17.0.0/ucd/auxiliary/GraphemeBreakTest.txt)；另验跨 Span/样式/字号边界、组合序列及产品不接纳范围的拒绝 |

算法层一致性试验保留全部用例数、失败及差异；产品准入子集另列，不用产品拒绝掩盖算法失败。若只实现规则子集，逐规则/测试行声明适用范围及排除原因，不称完整 UAX 符合。任何 tailoring 必须具名、版本化，说明替换规则、语言条件、额外用例和基线差异；无明确记录即采用上述默认策略。

布局在 UAX #14 允许的位置中选断点，同时保持完整 EGC，并结合 shaper 的边界安全信息决定是否重塑形；EGC、HB cluster 和合法断点不是同一个概念。所选断点改变上下文后，重新塑形并核对宽度、连接形式和逐行 bidi 顺序；有界搜索不收敛时明确失败。

若算法选型未完成但要先验证 writer 消费，可交付单独的**手工受限原型**：只接纳 U+0020–U+007E 和 LF/CRLF，固定 LTR，只在显式换行处分行，超宽拒绝，不自动折行；CRLF 作为一个换行单元。其他字符/方向控制、混排和自动断行请求均预检拒绝。此原型只关闭消费者实验，不关闭一般 N06b，也不宣称 Unicode bidi/断行/字素算法已经实现。

#### N06a 必须承载的解析后样式

最终结果在每个绘制 run 上绑定不可变的解析后样式快照（或结果内部不可变样式表索引），与源区间和字形 occurrence 明确关联。`StyleKey` 仅作来源标识，writer 不得再查询外部可变样式表。快照至少表达：已解析颜色及颜色空间、Fill/Stroke 开关与各自颜色/alpha、描边宽度及所用单位/连接等参数、有效透明度、实际 face 的物理 weight/italic、请求样式与实际选择结果、明确的合成粗体/斜体策略及其几何参数；无效或不支持组合在输出前拒绝。合成效果若影响 ink/bounds，必须在最终布局结果中计入，不能到 writer 才补算。

**首个 N06 消费者 profile 固定为不透明黑色 regular：** 已验证静态常规 face、Fill=true、黑色 DeviceRGB、Stroke=false、有效 alpha=1、无合成粗体/斜体。结果仍显式携带这些值；其他颜色、透明度、描边、粗斜体/合成样式请求在 preflight 拒绝。这个范围只限制新的 N06 入口，不改变既有 Flow 或 PR78 的功能。扩展这些样式时另加样式组合及跨出口验收，不凭新增字段开放支持。

颜色等 paint 边界落在同一共享连字/cluster 内时，首版拒绝冲突，不任取第一段样式或分裂现成字形；后续若支持，应明确 itemization/重塑形策略并重新测量。回归须证明：源样式对象在布局后改变不影响快照，所有 glyph 使用绑定的样式，PDF/SVG/OFD 同一最终结果的可见样式相符；固定 profile 的范围外请求不会留下假成功输出。
