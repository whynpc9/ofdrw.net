# R22 independent readers and original glyph checks

The older `make-*` and `summarize.py` retain the historical diagnostic matrices.
Their PdfPig default word/order score is **not** the current RTL logical gate.
See [the reader decision](../../../docs/validation/r22-reader-replacement-candidate.md)
and [the current export checkpoint](../../../docs/validation/r22-two-word-export-validation.md).

The bounded replacement uses PDFKit 1451.5.3 whole selection and logical/reversed
Find, PdfPig 0.1.15 raw letters, Poppler 26.09.0 physical word rectangles,
pypdf 6.21.2 and fontTools 4.68.0. Install the Python dependencies in a task-local
virtual environment. Check hashes before reading any PDF. These scripts do not
load a product assembly and do not launch Preview.

`character-probe/PdfPigProbe.csproj` takes `inputs.json output.json`. The input
has an `inputs` array of `{role, path, sha256, source}`. It records both
`UseActualText` modes, unmodified `Page.Text`, `GetWords()`, letter scalars,
baselines, rectangles, rendering modes and the reader assembly identity.
Build single-node with the repository's task-local .NET environment and shared
exclusive launcher, then run the built DLL.

```sh
python verify-character-gids.py inputs.json pdfpig.json FONT.ttf characters.json
python verify-visible-glyphs.py sample.ofd sample.pdf FONT.ttf visible.json
```

The first checks Type0 Identity-H/TrueType scalar → CID → embedded GID outline
and advance against the pinned original face, then matches each same-scalar
PdfPig baseline within 0.1 pt per axis. Only translation text matrices are
admitted; unsupported reference controls are recorded with `--record-controls`.
Without that option, any failure returns a nonzero exit status. It does not
use PDFKit logical string indices as character positions.

The second is deliberately restricted to the generated one-font, one-page R22
archive layout. It reads the actual OFD XML, embedded subset, original GIDs and
explicit origins, and constructs independent fontTools cubic contours. Every
painted PDF path must correspond one-to-one at those actual positions with a
maximum 0.002 pt coordinate error, opaque black nonzero fill and no extra paths.
The limit was fixed before product inspection; PDFsharpCore 1.3.67's pinned
source uses `0.####` path operands, within the conservative ceiling. Missing,
duplicated and shifted visible glyph controls must fail. Hidden semantic
carriers cannot satisfy this visible-path check. An empty corpus cannot pass.

PDFKit word Find bounds are separately associated one-to-one with Poppler
`pdftotext -bbox` physical rectangles, converting its top-left Y by page height:
X/Y centers within 1/2 pt and overlap at least 95% X / 60% Y of the smaller box.
Poppler token strings are retained as observations, not RTL logical oracles.
Actual Preview page inspection, actionable Find and original copy remain a
separate GUI gate on the exact generated bytes.
